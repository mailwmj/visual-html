# Visual HTML — 模板扩展与渐进式扩展指南 (Template Extension Guide)

> **核心理念：基于“语义契约”的渐进式扩展**
> 为了保证底层 AI 大脑在解析长文本时能够稳定输出，系统依赖一套标准化的 HTML 语义组件。但对于上层视觉风格，我们鼓励**无限制的创意自由**。底层数据流保持标准互通，但上层的 HTML 扩展权和 CSS 渲染权完全开放。

当用户要求新增、扩展一套视觉风格模板时，请按照以下架构法则执行：

## 1. 创建模板专属目录
在 `references/styles/` 下创建一个以风格命名的新目录。命名规则要求小写中划线（kebab-case），例如 `references/styles/cyber-bento/`。
该目录下必须包含：
1. `tokens.md`：记录该风格的设计理念、色彩字典、字体栈与排版基准。
2. `scaffold-web.html` & `scaffold-ppt.html`：Web 端页面与 16:9 幻灯片脚手架。

## 2. 严禁模板继承（Clean Room Design 干净沙盒法则）
**为了避免硬编码样式污染（如上一个模板的特定背景光效、硬编码色值残留到新模板中），严禁直接复制其他已有的视觉模板（如 `obsidian-cyan`）来修改。**
正确的做法是：
1. 直接读取 `references/shared-components.md`。
2. 按照固定的基础组件顺序（如：Hero 大标题 -> Stats 数据卡 -> 文本段落 -> Timeline 时间轴 -> Cards 核心特性 -> Admonitions 提示框 -> 优劣对比 -> 页脚）搭建一个**纯净的、无任何 CSS 的 HTML 骨架**。
3. 完全从零开始（From Scratch），基于这套纯净的 DOM 树结构，纯粹依照目标设计语言编写 CSS。

## 3. 视觉样式的“暴力重构”与“全覆盖契约” (CSS 级别)
默认情况下，建议继承现有的通用 HTML 骨架（如 `.timeline`, `.stats-grid`, `.admonition`）。但**绝不限制视觉呈现**。
强烈鼓励通过现代 CSS (Grid / Flexbox / 伪元素 / 绝对定位) 将标准的 HTML 语义结构彻底改头换面：
*   **组件全覆盖法则（契约底线）**：全局规范库 `references/shared-components.md` 中列出的所有标准组件，在你的新模板 `tokens.md`（设计约定）和 `scaffold-web.html`（CSS 样式）中**必须全部有对应的设计体现和样式兜底**。绝对不允许漏写某个组件的 CSS，导致 AI 提取出该组件后在页面上变成“无样式的裸奔代码”。
*   **形态颠覆**：例如将原本等宽排列的 `.stats-grid` 通过 CSS Grid 改造成不对称的便当盒（Bento Box），或者纵向吸顶的侧边栏。
*   **装饰解耦**：利用 `::before`/`::after` 伪元素为基础标签添加复杂的几何切割、发光阴影或悬浮质感，而无需污染原生 HTML 标签。

## 4. 架构的生长：允许扩展全新组件 (HTML 级别)
如果现有的组件池无法满足新风格的创意表达（例如你需要一个全新的“全屏横向滚动跑马灯”或“3D 翻转卡片”）：
**完全允许在专属的 HTML 脚手架中发明全新的 DOM 结构。**
*   **唯一约束（契约）**：新发明的组件，必须同步提取其核心的结构 HTML 与基础 CSS，反向注册到全局规范库 `references/shared-components.md` 中。
*   **架构收益**：一旦注册，这个新组件就正式成为了系统的“公共语义词汇”。底层的 AI 解析大脑日后就多了一种强大的排版武器；其他现存的旧模板也能获得该组件的基础兜底样式，实现架构的共同进化。

## 5. 允许做减法与优雅降级
设计不仅仅是做加法。如果新风格（如极简禅意风）认为现有的某些高级组件（如“优劣势对比卡片”）显得过于冗余或厚重：
*   完全允许在专属 CSS 中使用 `display: none;` 按需屏蔽特定子元素（如隐藏 icon、边框或背景色）。
*   或者通过抹除所有结构化外观，将其视觉降级为最极简的纯文本排版。

## 6. 制定核心 Design Tokens
在 `<style>` 内的 `:root` 准确定义变量：
* **背景架构**：若需全局光晕或复杂网格，推荐挂载在 `body` 级的 `background` 属性中（利用多层叠加），避免挂载在局部的 `<section>` 上导致长页面滚动时发生重影污染。
* **字体防呆**：指定中文字体（如 `Microsoft YaHei`）时，**必须同时写入中文别名 `"微软雅黑"`** 兜底，否则 Windows 系统极易崩坏降级至带有严重锯齿的“宋体”。（引入 Google Fonts 务必加 `&display=block` 避免排版闪跳）。

## 7. 最终并网注册
开发与质检完成后，返回 `SKILL.md` 大脑，在顶部的【设计风格与对应的目标场景清单】表格中，新增该模板的 `Style ID`、核心视觉特征和触发关键词，完成能力的最终注册。
