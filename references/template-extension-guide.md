# Visual HTML — 模板扩展与渐进式扩展指南 (Template Extension Guide)

> **核心理念：基于“语义契约”的渐进式扩展**
> 为了保证底层 AI 大脑在解析长文本时能够稳定输出，系统依赖一套标准化的 HTML 语义组件。但对于上层视觉风格，我们鼓励**无限制的创意自由**。底层数据流保持标准互通，但上层的 HTML 扩展权和 CSS 渲染权完全开放。

当用户要求新增、扩展一套视觉风格模板时，请按照以下架构法则执行：

## 1. 创建模板专属目录
在 `references/styles/` 下创建一个以风格命名的新目录。命名规则要求小写中划线（kebab-case），例如 `references/styles/cyber-bento/`。
该目录下必须包含：
1. `tokens.md`：记录该风格的设计理念、色彩字典、字体栈与排版基准。
2. `scaffold-web.html` & `scaffold-ppt.html`：Web 端页面与 16:9 幻灯片脚手架。
3. `preview.svg`：该风格专属的微缩视觉名片（`400×240` 矢量文件），用于在对话与画廊中直观展示。

## 2. 严禁模板继承与“防偷懒”工作流 (Anti-Laziness Workflow)
**为了避免硬编码样式污染（如上一个模板的特定背景光效残留），严禁直接复制其他已有的视觉模板（如 `obsidian-cyan`）来修改。**
同时，**为了从源头杜绝 AI 在生成长 HTML 代码时偷懒省略（如输出 `<!-- 省略部分演示 -->`）**，绝对不允许 AI 从零手写组件 DOM 树。

**唯一正确的工作流（强制要求）：**
1. **复制基座**：新建风格时，AI 必须使用终端命令或文件工具，直接将 `references/_base-scaffold-web.html` 完整拷贝到新目录，命名为 `scaffold-web.html`。该基座已经包含了 `shared-components.md` 中所有 19 个核心组件的纯净、完整 DOM 结构。
2. **重写样式**：AI 只能针对新拷贝的 `scaffold-web.html` 中的 `<style>` 标签区域进行覆盖修改（可以使用替换或正则操作），纯粹依照目标设计语言编写全新 CSS。
3. **禁止删减**：绝不允许在代码生成时以“节约字数/代码”为由，删除或注释掉基座文件中的任何 HTML 组件节点。必须保持 100% 结构全覆盖。

## 3. 视觉样式的“暴力重构”与“全覆盖契约” (CSS 级别)
默认情况下，建议继承现有的通用 HTML 骨架（如 `.timeline`, `.stats-grid`, `.admonition`）。但**绝不限制视觉呈现**。
强烈鼓励通过现代 CSS (Grid / Flexbox / 伪元素 / 绝对定位) 将标准的 HTML 语义结构彻底改头换面：
*   **组件全覆盖法则（契约底线）**：全局规范库 `references/shared-components.md` 中列出的所有标准组件，在你的新模板 `tokens.md`（设计约定）和 `scaffold-web.html`（CSS 样式）中**必须全部有对应的设计体现和样式兜底**。绝对不允许漏写某个组件的 CSS，导致 AI 提取出该组件后在页面上变成“无样式的裸奔代码”。
*   **形态颠覆**：例如将原本等宽排列的 `.stats-grid` 通过 CSS Grid 改造成不对称的便当盒（Bento Box），或者纵向吸顶的侧边栏。
*   **装饰解耦**：利用 `::before`/`::after` 伪元素为基础标签添加复杂的几何切割、发光阴影或悬浮质感，而无需污染原生 HTML 标签。

## 4. 架构的生长：允许扩展全新组件 (HTML 级别)
如果现有的组件池无法满足新风格的创意表达（例如你需要一个全新的“全屏横向滚动跑马灯”或“3D 翻转卡片”）：
**完全允许在专属的 HTML 脚手架中发明全新的 DOM 结构。**
*   **唯一约束（契约）**：新发明的组件，必须同步提取其核心的结构 HTML 与基础 CSS，反向注册到全局规范库 `references/shared-components.md` 中。
*   **架构收益**：一旦注册，这个新组件就正式成为了系统的“公共语义词汇”。底层的 AI 解析大脑日后就多了一种强大的排版武器；其他现存的旧模板也能获得该组件的基础兜底样式，实现架构的共同进化。

## 5. 允许做减法与优雅降级
设计不仅仅是做加法。如果新风格（如极简禅意风）认为现有的某些高级组件（如“优劣势对比卡片”）显得过于冗余或厚重：
*   完全允许在专属 CSS 中使用 `display: none;` 按需屏蔽特定子元素（如隐藏 icon、边框或背景色）。
*   或者通过抹除所有结构化外观，将其视觉降级为最极简的纯文本排版。

## 6. 制定核心 Design Tokens 与组件契约 (tokens.md)
在编写 `tokens.md` 时，必须包含以下两部分：
1. **核心变量**：在 `<style>` 内的 `:root` 准确定义背景、色板与字体。若需全局光晕或复杂网格，推荐挂载在 `body` 级的 `background` 属性中，避免滚动污染。指定中文字体时，**必须同时写入中文别名 `"微软雅黑"`** 兜底。
2. **19项完整组件视觉契约**：在 `tokens.md` 中，**必须以列表形式，严格逐一（1到19）定义 `shared-components.md` 中所有 19 个标准组件在该风格下的视觉呈现规则**。绝对不允许只挑选 4-5 个组件敷衍了事。这确保了 AI 在使用该风格时，对每个组件都有确定的排版参数可供依赖。

## 7. 绘制专属微缩视觉名片 (preview.svg)
为确保用户在对话中能秒级感知风格质感，且**杜绝 AI 自动生成 SVG 时因估算错误导致文本与框体重叠**，必须严格遵循以下 **4 层隔离坐标系（4-Tier Vertical Grid）** 与标准模版：

### 📐 严格 4 层隔离坐标系规范 (400 × 240)
```text
┌─────────────────────────────────────────────────────────────┐ (0, 0)
│ [背景画布] <rect width="400" height="240" rx="8" ... />     │
│                                                             │
│ ─── Tier 1: Eyebrow 标头层 (y: 12 ~ 30) ─────────────────── │
│ • <g transform="translate(18, 12)">                         │
│ • 胶囊/标签高度: 18px, 文本基线: y=12..13                   │
│                                                             │
│ ─── Tier 2: 风格大标题层 (y: 44 ~ 60, 基线固定 y=58) ──────── │
│ • <g transform="translate(18, 58)">                         │
│ • 中文标题: font-size="16", x="0", y="0"                    │
│ • 英文副标: font-size="9", x="120~135", y="-1"              │
│ ※ 与 Tier 1 留有 14px 绝对安全间隔，零重叠                   │
│                                                             │
│ ─── Tier 3: 灵魂组件卡片层 (y: 72 ~ 192, 固定高度 120px) ───── │
│ • <g transform="translate(18, 72)">                         │
│ • 卡片外框: <rect width="364" height="120" rx="12" ... />   │
│   内部纵向子层（相对 0..120）：                             │
│   - Row 1 (标签/步骤): y = 14 (高度 18)                     │
│   - Row 2 (代表性主文): y = 42 ~ 46 (font-size: 13)         │
│   - Row 3 (次级说明文): y = 60 ~ 64 (font-size: 9)          │
│   - Row 4 (核心微组件/指标/按钮): y = 74 ~ 92 (高度 18~20)   │
│                                                             │
│ ─── Tier 4: 页脚与色盘层 (y: 206 ~ 226, 基线固定 y=220) ─────── │
│ • <g transform="translate(18, 220)">                        │
│ • Style ID: <text font-size="9" x="0" y="0">style_id: ...</text>
│ • 色盘圆点: <g transform="translate(260, -8)"> (14px 色块) │
└─────────────────────────────────────────────────────────────┘ (400, 240)
```

### ⚡ 强制执行的自动化验证
生成新风格的 `preview.svg` 后，**必须运行验证脚本**进行坐标层级与边界冲突检查：
```bash
python3 references/scripts/validate_previews.py
```
只有当输出 `✅ [PASS]` 时，才允许并网注册。

## 8. 最终并网注册 (Final Registration)
开发与质检完成后，执行双重注册：
1. **SKILL.md 注册**：在顶部的【1. 风格注册表 (Style Registry)】表格中，新增该模板的 `Style ID`、中文名称、核心视觉特征、推荐场景与关键词、以及 `preview.svg` 资产路径。
2. **全量画廊注册**：在 `references/style-gallery.html` 中新增一张对应的卡片，填入 `preview.svg`、分类标签、场景描述与复制按钮。
