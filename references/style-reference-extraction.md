# Style Reference Extraction Contract

本文件只在 Extend Style Pack 含有图片、截图、PPT/PPTX 等视觉参考，或用户明确要求从参考材料提炼风格时读取。它定义从参考证据到 Style Brief 的方法，不负责 scaffold、preview 或注册。

## 核心目标

参考材料是视觉证据，不是必须逐项实现的规格。默认采用 `Inspiration` 模式：提炼稳定、可复用、可跨内容和跨媒介迁移的设计规则，创造属于同一视觉家族的独立风格系统，而不是复刻某张图片或某套 PPT。

除非用户明确授权并具备可用权利，不复制或默认继承：

- 原文、Logo、品牌标识和真实业务数据。
- 人物、摄影、专有插画、图标资产和专有字体文件。
- 单页坐标、固定卡片数量、逐页构图和一次性装饰。
- 只在一处出现且没有系统性证据的视觉特例。

本阶段只输出 Style Brief。不得创建正式风格目录、完整 scaffold、preview 或 registry 记录。

## 1. 证据纪律

每项结论必须标记为以下一种：

- `Observed`：可以从参考材料直接观察。
- `Inferred`：为了形成完整设计系统而进行的合理推演。
- `Unknown`：参考材料无法证明，不假装已经观察到。

每项同时标注 `High / Medium / Low` 置信度。没有证据、又未标记为 `Inferred` 的规则视为提炼失败。

优先提取多次出现、占据主导地位、可以迁移到不同内容和页面的规律。不得把特定 Hero、卡片数量、文案长度、图表数据或装饰位置固化为全局模板规则。

## 2. 输入处理

### 2.1 单张图片或截图

单张图片只能证明当前画面的可见表现，不能证明完整设计系统。

重点提取：

- 色彩角色、对比关系和大致使用比例。
- 字体气质、字阶差异、对齐和排版密度。
- 留白、网格、空间节奏和视觉焦点。
- 圆角、边框、阴影、透明度和材质。
- 可重复使用的图形、纹理和装饰语法。

响应式、交互、动效、复杂组件和其他页面类型必须标记为 `Inferred` 或 `Unknown`。

### 2.2 多张图片或截图

先逐张记录证据，再提取跨图重复规律。区分同一系统的页面变体与彼此冲突的视觉方向；冲突项不自行平均或混合，交给用户确认。

### 2.3 PPT/PPTX

使用环境中可用的演示文稿读取与渲染能力检查整套文件。至少：

1. 渲染全部页面或联系表，不能只看封面或第一页。
2. 检查主题色、主题字体、母版、版式、占位符和背景资产。
3. 比较封面、章节、正文、数据、对比和结束页中的重复规律。
4. 将跨页稳定规则与单页特例分开记录。
5. 不把固定 16:9 坐标直接迁移为 Web 响应式布局规则。

若当前环境无法读取 PPT/PPTX 的主题或母版，只能依据渲染页观察，并明确标记该限制；不得根据文件名或第一页补全不存在的规则。

### 2.4 多源参考

多种参考的角色必须明确，例如“PPT 提供排版秩序，图片提供材质与色彩”。出现冲突时列出不同方案及影响；只有用户已明确主次时才自行选择。

## 3. 必须分析的视觉维度

| Dimension | 需要提取的内容 |
|---|---|
| Visual Atmosphere | 情绪、正式程度、视觉张力、克制或表现性 |
| Color System | Canvas、Surface、Text、Border、Accent 的角色、比例和语义 |
| Typography | 字体气质、层级、字重、行距、对齐、数字与标签风格 |
| Spatial Composition | 网格、留白、密度、对称性、阅读路径和焦点 |
| Shape Language | 圆角、切角、边框、线条、容器和控件轮廓 |
| Material & Depth | 扁平、纸张、玻璃、金属、发光、阴影和层级关系 |
| Signature Motifs | 可重复的图形、纹理、标记和装饰语法 |
| Imagery Treatment | 摄影、插画、图标、裁切、色调和背景处理 |
| Data Visualization | 数字、表格、图表、流程和比较的表达倾向 |
| Motion Hints | 只有材料提供证据时定义；否则标记 Unknown |

颜色提取关注“角色与关系”，不能只输出若干十六进制色值。字体不可直接获得时描述可观察特征并给出替代方向，不假设专有字体可用。

## 4. Style Brief 输出格式

### A. Style Essence

用一句具体语言描述风格的核心感受和设计机制，避免只写“高级、现代、科技感”等空泛形容词。

### B. Evidence Matrix

| Dimension | Evidence | Type | Portable Rule | Confidence |
|---|---|---|---|---|
| Color | 参考材料中的具体表现 | Observed | 可迁移的颜色角色与使用规则 | High |
| Layout | 参考材料中的具体表现 | Observed / Inferred | 可迁移的空间与节奏规则 | Medium |

每项 `Portable Rule` 必须能够应用到与参考主题无关的新内容。

### C. Core Visual DNA

只保留最有辨识度的 3–6 项。每项必须可以落实为颜色、排版、空间、形状、材质或图形规则，不能只是情绪形容词。

### D. Reference Boundary

- `Preserve`：应保留的核心视觉基因。
- `Adapt`：保留设计意图但需要重新构图或跨媒介转译的部分。
- `Exclude`：不得进入风格包的内容、资产和一次性构图。
- `Unknown`：缺少证据、后续需要推演或确认的部分。

### E. Draft Design Tokens

提出初步颜色角色、字体类别、字阶关系、圆角、边框、阴影、间距、材质和图形语法。Token 是草案；只有用户确认，或已按 Extend route 明确授权跳过确认后，才能固化为正式风格规范。

### F. Cross-Media Translation

- `Core DNA`：Web 与 PPT 必须共享的视觉基因。
- `Web Adaptation`：响应式长页面、滚动叙事、环境层和移动端降级。
- `PPT Adaptation`：固定 16:9、安全区、页型、投影对比和单页焦点。

Web 与 PPT 应属于同一视觉家族，但不要求采用相同空间结构或把一方机械缩放为另一方。

### G. Representative Proof Plan

- Web：Hero、长正文与一个数据/比较组件。
- PPT：封面页、正文页和数据页。
- 使用与参考材料主题无关的示例内容。

### H. Confirmation Summary

用简短语言说明准备保留的视觉基因、主动排除的内容、属于推演的规则，以及拟议名称、`style_id` 和类别。等待用户确认后进入 Style Architecture；用户已按 Extend route 明确授权跳过确认时，可以继续，但仍须保留完整 Style Brief 和参考边界。

## 5. 完成检查

- [ ] 每条核心规则有证据，或明确标记为 `Inferred`。
- [ ] 单图未被过度泛化；PPT 未只分析封面或第一页。
- [ ] 3–6 个 Core Visual DNA 足以形成辨识度，又不依赖原始内容。
- [ ] `Preserve / Adapt / Exclude / Unknown` 边界清晰。
- [ ] 未继承原文、Logo、品牌资产、专有插画或一次性构图。
- [ ] Web/PPT 转译共享视觉基因但符合各自媒介规律。
- [ ] Representative Proof Plan 能验证泛化，而非复现参考主题。
- [ ] 尚未创建正式风格目录或写入 registry。
